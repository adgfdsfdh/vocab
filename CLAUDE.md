# Vocab — личный англо-русский словарь (PWA)

Ввожу английское слово → перевод на русский (MyMemory API, показываем только перевод — без
транскрипции, аудио и примеров) → слово сохраняется → тренирую его
(карточки, 4 варианта, написание) по расписанию FSRS. Одна база на ПК (Windows) и планшете
(Xiaomi Pad 5) через Supabase, вход по magic link. Работает офлайн, синхронизируется при появлении сети.
Интерфейс на русском, есть компактный режим-виджет для узкого окна. Позже — обёртка Tauri 2 для Windows.

Пользователь не программист: объяснять коротко, по-русски, и явно писать, что нужно сделать руками.

## Стек
Vite + React + TypeScript · vite-plugin-pwa · Dexie (IndexedDB) · Supabase JS · ts-fsrs · Vitest.
Хостинг GitHub Pages, деплой через GitHub Actions. Позже Tauri 2.

## Только бесплатное
Приложение полностью бесплатное. Никаких платных сервисов, тарифов, триалов и ключей с оплатой.
- MyMemory — бесплатный лимит (с параметром `de=<email>` лимит выше); при исчерпании — понятная ошибка, не платный API.
- Supabase — только Free plan. Учитывать: бесплатный проект засыпает после ~7 дней без активности.
- GitHub Pages / Actions — бесплатно для публичного репозитория.
- Бэкап — через бесплатный «Google Диск для компьютера» (локальная папка), без Google API.
Если для функции нужен платный сервис — остановиться и спросить пользователя.

## Команды
- `bash init.sh` — полная проверка: npm install → typecheck → тесты → сборка. Итог PASS/FAIL.
- `npm run dev` — локальный сервер разработки: http://localhost:5173/vocab/
- `npm run preview` — посмотреть готовую сборку: http://localhost:4173/vocab/ (сначала `npm run build`)
- `npm run icons` — пересоздать PNG-иконки в public/.
- Сайт: https://adgfdsfdh.github.io/vocab/ — публикуется автоматически при `git push` в main (GitHub Actions).
- `npm test` — тесты Vitest. `npm run typecheck` — проверка типов. `npm run build` — сборка.

## Файлы харнесса
- `feature_list.json` — список функций F01–F11, критерии готовности, статусы.
- `claude-progress.md` — журнал сессий (новая запись сверху).
- `init.sh` — единая проверка готовности.
- Исходный план пользователя: `D:\english\2Словарь-тренажёр план и инструкции для Claude Code.docx`
  (вне репозитория). Его требования уже перенесены в `feature_list.json`; при расхождении — спросить.

## Правила
1. **Одна функция за сессию.** Берём первую по порядку со статусом `todo` (или `in_progress`).
2. **Функция готова (`done`) только когда `bash init.sh` даёт PASS** и выполнены все её acceptance_criteria.
3. **Не менять acceptance_criteria и verification, чтобы скрыть недоделки.** Не удалять и не ослаблять тесты.
   Изменить критерии можно только с явного согласия пользователя, с записью причины в журнал.
4. **Секреты только в `.env.local`** (он в `.gitignore`). Репозиторий публичный.
   - В коде/браузере допустимы только `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` (публичные по замыслу, защищены RLS).
   - `service_role` key — никогда с префиксом `VITE_`, никогда в коде, коммитах, логах и GitHub Actions.
   - Перед коммитом проверить `git status`/`git diff --cached` на отсутствие ключей.
5. **В конце сессии:** обновить `claude-progress.md` и `feature_list.json` (status), затем `git commit`.
6. Ручные шаги пользователя (создать проект Supabase, вставить ключи, включить Pages и т.п.) —
   выписывать отдельным списком «Что сделать руками». Ключи пользователь вставляет в `.env.local` сам,
   никогда не просить присылать их в чат.
7. **В конце функции:** запустить `init.sh` и показать вывод, запустить dev-сервер, дать адрес и
   объяснить, что проверить руками и как.
8. **Ревью-сессии** (после F06 и в конце): отдельная сессия-ревьюер не правит код, а проверяет каждую
   `done`-функцию по критериям и записывает вывод в `claude-progress.md`.

## Порядок старта сессии
1. Прочитать этот файл, затем последние записи `claude-progress.md`.
2. `git log --oneline -10` и `git status` — понять текущее состояние.
3. Запустить `bash init.sh` — убедиться, что база рабочая. Если FAIL — сначала чинить.
4. Открыть `feature_list.json`, выбрать одну функцию, поставить ей `in_progress`.
5. Сделать функцию, написать тесты из `verification`, добиться PASS в `init.sh`.
6. Закрыть сессию по правилу 5.
